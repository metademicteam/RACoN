Resource-Aware Collaborative Network

Pool your PCs for local-first AI inference.

RACoN runs one model across several Windows PCs. Each machine keeps its own memory, and the scheduler splits the model's layers by each PC's free capacity. If a worker goes offline, its layers move back to the main PC.

What RACoN is

Local-first desktop app

A native Windows app (PySide6) with hardware telemetry, a scheduler lab, benchmark history and a chat panel. Everything runs on your machine by default.

Honest metrics

Hardware that does not expose real numbers, such as the Intel UHD 630 GPU, reports Unavailable instead of a made-up figure. Simulated results are labeled as simulated.

Safe by design

Workers run only allow-listed task types. Public API calls need an API key. Admin controls stay on loopback and are never published.

How it works

  1. Install the Windows installer on each PC. It installs per-user and needs no admin rights.
  2. Join the cluster over Tailscale. Workers expose only a single Tailscale address for layer traffic.
  3. Serve the model. The head PC measures each device and assigns layers in proportion to free memory.
  4. Call the OpenAI-compatible API at racon.metademic.org/v1 with an API key.

Model weights and activations never travel over the public internet. Only API requests and responses do. Multiple PCs do not form a single pooled RAM or VRAM space.

Public API

An OpenAI-compatible gateway in front of the model. Any OpenAI client works with it.

curl https://racon.metademic.org/v1/chat/completions \
  -H "Authorization: Bearer rk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"model":"gemma-3-1b","messages":[{"role":"user","content":"Hello"}],"max_tokens":64}'
  • Endpoints: /v1/chat/completions, /v1/completions, /v1/embeddings, /v1/models
  • Auth: Authorization: Bearer rk_… (keys are issued by the operator; only SHA-256 digests are stored)
  • Limits: 30 requests/min per client IP, 60 requests/min per key, max_tokens up to 2048
  • Errors: 401 bad key, 429 rate limit (see Retry-After), 503 model offline

Public workloads may be visible to the operator of the machine that runs them. Do not send personal, confidential, medical, financial or credential data.
